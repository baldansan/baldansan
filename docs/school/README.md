# Сургууль / анги — тэмдэглэл

## Хүүхдийн бүртгэл (имэйлгүй сурагч) — migration 065

Бага насны хүүхэд (жишээ нь 1А ангийн 6 настай сурагч) имэйлгүй тул эцэг эх эсвэл ангийн багш
хүүхдийн бүртгэл үүсгэнэ. Хүүхэд утсан дээр avatar-аа дараад 4 оронтой PIN-ээр нэвтэрнэ.

### Тохиргоо

| Env var | Шаардлага | Тайлбар |
| --- | --- | --- |
| `SUPABASE_SERVICE_ROLE_KEY` | **Заавал** | Хүүхдийн auth хэрэглэгч үүсгэх/нэвтрүүлэх/устгах. Зөвхөн server route-д. Байхгүй бол `/family`, `/kids`, багшийн хуудас найрсаг тайлбар харуулна. |
| `KIDS_PASSWORD_SECRET` | Сонголттой (санал болгоно) | Хүүхдийн нууц үгийг `HMAC-SHA256(secret, child_user_id)`-ээр гаргана. Байхгүй бол `SUPABASE_SERVICE_ROLE_KEY`-г secret болгоно. **Нэг удаа тохируулаад бүү соль** — солибол одоо байгаа хүүхдүүд нэвтэрч чадахгүй. |

Supabase SQL editor дээр `supabase/migrations/065_kid_profiles.sql`-г ажиллуулна (дахин ажиллуулахад аюулгүй).
Урьдчилсан нөхцөл: 011/013 (classrooms, `can_manage_org_classroom`), 064 (ангийн код).

### Урсгал

1. **Эцэг эх** `/family` (Профайл → «👨‍👩‍👧 Гэр бүл — хүүхдийн бүртгэл») → «Хүүхэд нэмэх»: нэр, avatar, PIN ×2,
   сонголтоор багшийн өгсөн 6 оронтой ангийн код. **Багш** ангийн хуудасны «Хүүхдийн бүртгэл (имэйлгүй сурагч)»
   хэсгээс нэмбэл хүүхэд шууд тэр ангид орно (асран хамгаалагч = багш).
2. `/api/kids/create` (service role): `auth.admin.createUser` — имэйл `kid-<uuid>@kids.buunduu.mn`
   (имэйл хэзээ ч очихгүй), нууц үг гаргалгаатай, хадгалагдахгүй. `kid_profiles`-д `pin_hash = sha256(child_id + pin)`.
   Ангийн код байвал `classroom_students`-д идэвхтэй сурагчаар шууд нэмнэ.
3. **Хүүхэд нэвтрэх**: нэвтрэх хуудасны «🧒 Хүүхэд нэвтрэх» → `/kids` → avatar → PIN → `/api/kids/login`
   (асран хамгаалагч эсвэл ангийн багш тэр төхөөрөмж дээр нэвтэрсэн байх ёстой) → хүүхдийн session token →
   browser `setSession` → `/home`. Onboarding түлхүүрүүдийг (хятад, HSK 1) автоматаар тохируулна.
4. **Хүүхдийн горим**: `localStorage["buunduu-kid-mode-v1"] = child_user_id`. Аппын дээд талд «🧒 нэр» +
   «Эцэг эх» товч; профайл хялбаршуулсан (ангид орох, бүртгэл устгах, гарах нуугдана).
   «Эцэг эх» → хүүхдийн session хаагдана → `/login?next=/family` (эцэг эхийн имэйл бөглөгдсөн,
   `localStorage["buunduu-guardian-email-v1"]`). Эцэг эхийн хэл/түвшний тохиргоо сэргээгдэнэ.
5. Бүх ахицын хүснэгт `auth.uid()`-аар ажилладаг тул хүүхэд бүрийн ахиц өөрийн бүртгэлд тусдаа хадгалагдана.

### Route-ууд

| Route | Хэн | Юу |
| --- | --- | --- |
| `GET /api/kids/list[?classroomId=]` | Эцэг эх / ангийн багш | Хүүхдийн жагсаалт (анги, сүүлд идэвхтэй, streak) |
| `POST /api/kids/create` | Нэвтэрсэн том хүн | Хүүхэд үүсгэх (асран хамгаалагч = дуудагч) |
| `POST /api/kids/login` | Асран хамгаалагч / ангийн багш | PIN шалгаад хүүхдийн token буцаана (5 буруу PIN → 60 сек түгжээ) |
| `POST /api/kids/update` | Асран хамгаалагч | Нэр, avatar, PIN, анги солих |
| `POST /api/kids/delete` | Асран хамгаалагч | Хүүхдийн өгөгдөл + auth user бүрмөсөн устгах |

RLS: асран хамгаалагч өөрийн мөрүүдийг select/update/delete; ангийн багш (`can_manage_org_classroom`)
өөрийн ангийн мөрүүдийг select. Insert зөвхөн service role. Тайлангийн RLS-д `public.is_guardian_of(child)` ашиглана.
