# Хөх хотын их сургуулийн хөтөлбөрийн демо өгөгдөл (500 оюутан)

Файл: `supabase/demo/seed-hohhot-500.sql`

Өвөр Монголын Их Сургуулийн Монгол оюутны хятад хэлний хөтөлбөрийн тэнхимийн
эрхлэгчид үзүүлэх демо. Самбарууд «амьд» харагдахын тулд 60 хоногийн
идэвх, сайн / дунд / сул ангиуд, од оюутнууд, хоцорч буй оюутнууд,
идэвхгүй оюутнууд, тэнцээгүй шалгалтуудыг бодитоор үүсгэнэ.

> ЭНЭ БОЛ ЖИШЭЭ ӨГӨГДӨЛ. Бүх нэр зохиомол, бүх дүн тооцоолж үүсгэсэн.
> Үзүүлбэр дээр «системийн боломжийг харуулсан жишээ өгөгдөл» гэж хэлнэ.

## Юу үүсгэх вэ

| Зүйл | Тоо |
| --- | --- |
| Байгууллага «Өвөр Монголын Их Сургууль — Монгол оюутны хятад хэлний хөтөлбөр» (`university`) | 1 |
| Эрхлэгч (`owner`) + багш (`teacher`) — `organization_members` | 1 + 20 |
| Анги «1-р анги · 1班» … «20-р анги · 20班» (join_code `530101`…`530120`) | 20 |
| Оюутан (анги бүр 25, `oyutan<N>@example.mn`) | 500 |
| Хөтөлбөр (066): курсын эхний 10 хичээл / анги — `assignments.is_curriculum` | 200 |
| Энгийн даалгавар (анги бүр 2 + хамгийн сул оюутанд 1 зорилтот) | 60 |
| Дууссан хичээл (`user_lesson_progress`), quiz оролдлого, асуулт тус бүрийн хариулт | ~3 мянга / ~5 мянга / ~40 мянга |
| Идэвхийн хугацаа (`user_activity_sessions`), өдрийн идэвх, streak | ~40 мянга / ~35 мянга / 500 |
| Тоглоомын үр дүн, видео үзсэн ахиц | ~15–20 мянга / ~1 мянга |
| Оноо (`user_points_ledger`, `_daily`, `_totals`) | ~55–60 мянга / ~16 мянга / 500 |
| Ирц (Да/Лх/Ба × 8 долоо хоног) | ~12 мянга |
| Ангийн шалгалт (`classroom_exams`): анги бүр өнгөрсөн 1 + сондгой ангид удахгүй болох 1 | 30 |
| Шалгалтын дүн (`user_test_attempts`, HSK3/HSK4 загвар, босго 180/300) | ~450 |
| Хурдан сорил (`class_quizzes`, 12 асуулт) + оролдлого | 20 / ~400 |
| Ангийн чат өрөө | 20 |

Нийт ойролцоогоор 200 мянга орчим мөр, ажиллах хугацаа ~10–40 секунд.

### Загварчлал

- Анги бүрийн багшийн чадвар 0.35 … 0.95 (сайн: 1, 4, 9, 14, 17, 20 · сул: 5, 11, 15). Оюутны
  чадвар = ангийн түвшин ± шуугиан.
- Анги бүрт 3–5 «од» (өндөр чадвар, өдөр бүр суралцана, 3 орчим дахин олон оноо),
  2–3 «хоцорч буй» (чадвар доогуур, идэвх бага, ирц муу).
- 30 оюутан (6%) сүүлийн 14+ хоног ямар ч идэвхгүй. Тэд самбарын «Анхаарах» жагсаалтад гарна.
- Оюутан бүр нэг сул талтай: 30% дүрэм (`grammar`), 25% үгийн дасгал (`word_practice`),
  20% шалгалт/quiz (`quiz`), 25% тэнцвэртэй.
- Шалгалтын тэнцэх хувь ангиар 30% … 96% хооронд (чадвартай шууд уялдана).
- Бүх «санамсаргүй» тоо `setseed(0.42)` + md5 хэшээр тогтмол: ажиллуулах бүрт ижил харагдана.
- Хичээл: `fazhan-chuji1-l01…l10` (1–12-р анги), `fazhan-chuji2-l01…l10` (13–18),
  `fazhan-zhongji1-l01…l10` (19–20). Асуулт, видео, mock_tests-ийг ажиллах үед
  production-оос жинхэнээр нь сонгоно (олдохгүй бол тухайн хэсгийг алгасана).

## Хэрхэн ажиллуулах

1. Supabase → **SQL Editor** → шинэ query.
2. `seed-hohhot-500.sql`-ийн бүх агуулгыг хуулж оруулаад **Run**.
3. Төгсгөлд мөрийн тооны хүснэгт гарна (organizations = 1, classrooms = 20, classroom_students = 500 гэх мэт).

Дахин ажиллуулахад аюулгүй: скрипт эхлээд ЭНЭ seed-ийн өмнөх өгөгдлийг (`2001`–`2022` төрлийн ID)
устгаад дахин үүсгэнэ. Хуучин `seed-training-center.sql`-ийн өгөгдөлд хүрэхгүй.

Шаардлагатай миграц: 009, 011–013, 038, 041, 042, 045/046, 050, 054, 057–059, 064, 066, 071, 073, 074.
Дутуу бол скрипт эхэндээ тодорхой алдаа өгч зогсоно.

### Яагаад FK-г түр унтрааж байна вэ

Демо хэрэглэгчид `auth.users`-д байхгүй. Харин `question_attempts`, `user_activity_sessions`,
`user_game_results`, `user_video_progress`, `user_test_attempts`, `user_points_*`, `chat_*` хүснэгтийн
`user_id` нь `auth.users`-д FK-тэй. Тиймээс скрипт зөвхөн өөрийн transaction-д
`session_replication_role = replica` болгоно (FK + триггер түр унтарна), төгсгөлд `origin` болгож буцаана.
`supabase db dump --data-only`-ийн гаралт мөн ийм горим ашигладаг тул SQL Editor-ийн `postgres` эрхээр ажиллана.
Хэрэв «permission denied to set parameter session_replication_role» алдаа гарвал postgres
хэрэглэгчээр холбогдсон `psql`-ээр ажиллуулна.

Үүнээс үүдэх зүйлс:

- `user_points_daily` / `user_points_totals`-ийг (071-ийн триггер ажиллахгүй тул) скрипт өөрөө
  `user_points_ledger`-ээс тооцож бөглөнө — триггертэй яг ижил дүн.
- Ангийн чат өрөөг (074-ийн триггер) скрипт өөрөө үүсгэнэ (`owner_user_id = NULL`).

## Алгассан зүйлс

- `user_public_profile` — `auth.users`-д FK, демо хэрэглэгч байхгүй. Тиймээс «Шилдэг сурагчид» (нийтийн) жагсаалтад
  демо оюутнууд гарахгүй; байгууллагын самбарын «Шилдэг оюутнууд» нэрийг `classroom_students`-ээс авдаг тул харагдана.
- Чатын гишүүд / topic өрөө / мессеж — `chat_members.user_id`, `chat_rooms.owner_user_id` нь `auth.users`-д FK.
- `user_vocabulary_progress` (сурсан үгс) — хэмжээ ихтэй, самбар нь үүнийг уншдаггүй.

## Нэвтрэх / харах

Демо эрхлэгч, багш нар нь `auth.users`-д БАЙХГҮЙ (зөвхөн ID) тул тэдний нэрээр нэвтэрч **болохгүй**.
Бодит админ эрхээрээ нэвтэрч бүгдийг харна:

- Эрхлэгчийн самбар: `/organization/d0000000-0000-4000-8000-200100000001/dashboard`
- Байгууллагын ID: `d0000000-0000-4000-8000-200100000001`
- Ангийн join code: `530101` … `530120` (зөвхөн үзүүлэх; жинхэнэ хэрэглэгч нэгдвэл жинхэнэ сурагч болно)
- Эрхлэгч: «Д. Гантулга (тэнхимийн эрхлэгч)» (`owner`), багш нар: `bagsh1@example.mn` … `bagsh20@example.mn`

Захирлын самбар демо ангиудыг ӨГЧ БАЙДЛААР НУУНА («N жишээ анги нуугдсан байна»). Дээд талын шар хэсэгт
**«Жишээг харуулах»** товчийг дарна — тэгэхэд 20 анги, 500 оюутан бүгд «Жишээ» тэмдэгтэй гарна
(`isDemoId` — `d0000000-0000-4000-8000-` угтвараар). Үзүүлбэрийн өмнө үүнийг асаахаа мартуузай.

Анхаарах: самбар «сүүлийн шалгалт» гэж огноогоор хамгийн сүүлийн шалгалтыг авдаг. Тиймээс удахгүй болох
шалгалтыг зөвхөн сондгой ангид үүсгэсэн — тэгснээр тэгш ангиудад «Сүүлийн шалгалтад тэнцээгүй» оюутнууд
«Анхаарах» жагсаалтад харагдана.

## Устгах

`seed-hohhot-500.sql`-ийн **«1. ЦЭВЭРЛЭХ»** хэсгийг (`do $cleanup$ … end $cleanup$;`) дангаар нь хуулж ажиллуулна.
Энэ нь зөвхөн `2001`–`2022` төрлийн ID-тай мөрийг устгана; бусад өгөгдөл, хуучин сургалтын төвийн seed хэвээр үлдэнэ.

> Хуучин `seed-training-center.sql`-ийн цэвэрлэгээ `d0000000-0000-4000-8000-%` угтвартай БҮХ анги/сурагч/байгууллагыг
> устгадаг. Тиймээс түүнийг ажиллуулсны дараа энэ seed-ийг дахин ажиллуулна (эхний цэвэрлэгээ үлдэгдлийг арилгана).

## Нэмэлт шалгах query (анги бүрээр)

```sql
select c.name as angi,
       c.course_id,
       count(distinct cs.student_user_id) as oyutan,
       round(avg(t.total)) as dundaj_onoo,
       round(100.0 * count(*) filter (where (a.score_metadata ->> 'passed')::boolean)
             / nullif(count(a.id), 0)) as shalgalt_tenssen_pct
  from public.classrooms c
  join public.classroom_students cs on cs.classroom_id = c.id
  left join public.user_points_totals t on t.user_id = cs.student_user_id
  left join public.user_test_attempts a on a.user_id = cs.student_user_id
 where c.id::text like 'd0000000-0000-4000-8000-2003%'
 group by c.id, c.name, c.course_id
 order by c.id;
```
